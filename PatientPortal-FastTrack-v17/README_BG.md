# Patient Portal v1.17 — Fast Track17

**Само синтетични данни. HOLD / NO-GO.**

Потребителят потвърди на Windows работещ ClamAV16, проверка на наследен PDF, ново качване/публикуване, преглед/изтегляне от собственика и отказ за друг пациент. Това е ръчна функционална проверка, не независимо одобрение. Точният обхват е в WINDOWS_ACCEPTANCE_BG.md.

Следващата стъпка е **криптиран архив и пробно възстановяване**. Извлечи целия v17 ZIP в нова папка. Запазват се познатият собствен FastTrack15 desktop root/schema1, candidate/schema2, потребителите и настройките. Няма ново init/миграция/reset. Използва се вече подготвената Python среда; старият ClamAV16 може да остане отворен.

1. Спри своя портал8000 с Ctrl+C.
2. Отвори **BACKUP_WINDOWS.cmd** и въведи два пъти нова парола за архива от поне16 знака.
3. **RESTORE_TEST_WINDOWS.cmd** възстановява последния собствен архив в нова отделна папка.
4. **START_RESTORED_WINDOWS.cmd** отваря възстановеното копие на127.0.0.1:8001 за проверка.

Подробности: **WINDOWS_BACKUP_BG.md**. Първоначалните данни не се заменят, не се спират чужди процеси и няма Windows service/firewall/registry/ACL/PATH промени. Възстановените runtime locks се създават наново по съществуващия encrypted backup API.

Поправено е изричното затваряне на двете read-only SQLite връзки при candidate конфигурационната проверка, за да не остават файлови handles при Windows directory rename/cleanup. `app/portal.py`, криптираният формат и предишните тестови файлове са запазени. Българският интерфейс е същият с етикетv1.17 за новия source.

Проверка: `python -B tools/fasttrack_runner.py --include-synthetic`. Всички18 групи се пазят; група18 изпълнява15 първоначални backup проверки и11 нови desktop случая. TEST_REPORT_BG.md описва реалното изпълнение и границите му. Новите CMD/getpass/Windows restore действия не са изпълнявани в Linux; целевият ръчен backup тест предстои.

В source/ZIP няма пароли, DB, PDF, ключове, .ppbk, runtime или ClamAV EXE/DLL/CVD. Предишните source releases и архиви са запазени отделно. Реални пациенти изискват отделно независимо одобрение.

Корекцията затваря изрично и новосъздадената lifecycle SQLite връзка след commit, преди преименуване на възстановената директория. Проверен е и запазеният marker след затварянето.
